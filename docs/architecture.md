The prediction path begins with a client request to the FastAPI /predict endpoint carrying V1-V28 and Amount features aligned to the ULB schema. The service loads a pre-trained XGBoost artifact from models/model.joblib at startup, performs inference, emits Prometheus counters and histograms for request volume, fraud-class decisions, and score distribution, and asynchronously writes a per-request JSON log to S3 under prediction-logs/date=YYYY-MM-DD for replayable operational audit. Model lifecycle is separated from serving lifecycle: training and evaluation are executed offline, metrics and parameters are tracked in MLflow, and deployment consumes a registry-selected champion version through CI rather than retraining during release.

The monitoring path branches from both online and batch signals. Prometheus continuously scrapes API metrics and Grafana evaluates alert rules over fraud-rate behavior relative to the 0.17% dataset baseline, while a scheduled drift_check batch script pulls current-day S3 prediction logs, compares feature distributions against the 5,000-row reference baseline via Evidently DataDriftPreset, and pushes drift aggregate gauges to Pushgateway for Prometheus ingestion. Grafana combines live and pushed metrics into one dashboard surface and routes threshold breaches to configured email contact points, so the same telemetry pipeline supports both incident simulation and real on-call response workflows.
