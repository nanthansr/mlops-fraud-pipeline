How does this model evaluate risk?

Machine learning models look at the combination of behaviors rather than a single metric like the dollar amount. The 28 PCA variables (V1–V28) capture transaction context such as merchant matching, card behavior velocity, and device security indicators.

💡 The Concept: Dollar amounts are not inherently fraudulent. High values (e.g., $1,299.00) can be legitimate if the context is normal. Conversely, low values (e.g., $1.00) can be highly suspicious if device or velocity markers fail.

🔧 Try it: Load Legitimate Preset 2 ($1,299.00) and run prediction. Then, load Fraudulent Preset 1 ($1.00) and run. You'll see that V-features carry the real prediction weight. Customize the Amount or toggle Advanced PCA Features below to experiment!

How the pipeline works
1

Train

XGBoost on 284K transactions (577:1 imbalance, handled via scale_pos_weight). PR-AUC is the primary metric — not ROC-AUC.

2

Register

MLflow tracks experiments, stores artifacts in S3, and promotes the best model to @champion alias.

3

Serve

FastAPI with typed request schemas. Every prediction emits Prometheus counters and histograms.

4

Monitor

Prometheus scrapes request rate, fraud rate, and confidence distributions. Grafana dashboards visualize trends.

5

Detect drift

Evidently batch job compares live predictions against a reference distribution. Drift metrics go to Pushgateway.

6

Alert

Grafana fires alerts when fraud rate spikes above 3× baseline or more than half of features drift simultaneously.
